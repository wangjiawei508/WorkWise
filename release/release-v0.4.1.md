# WorkWise 0.4.1 候选说明

0.4.1 是 0.4.0 的修复版本，重点解决错误 0.4.0 的应用内升级、精选插件市场展示和本地 Skill 边界问题。

## 关键修复

- 正式发布后，已安装错误 0.4.0 的用户可通过应用内更新升级到 0.4.1。
- 候选代码会把 0.4.0 视为撤回版本；但截至 2026-08-11，公开 GitHub Release 和 stable 清单仍指向 0.4.0，尚未执行撤回或回滚。
- 0.4.1 当前仅为待确认候选版本，获得明确发布批准后才可推广到 stable。
- 更新失败按未签名构建、清单、网络、签名、下载和安装错误分类，不再把自动更新失败伪装成官网跳转。
- 插件市场只展示 11 个精选插件，按用户任务分类；本地 Skill 保留在独立技能页，不混入精选市场。
- 插件详情补齐产品类型、实现方式、权限、认证、许可证、来源、依赖和健康状态。
- 保留旧插件配置、Skill、凭据引用和迁移兼容，不静默删除用户数据。

## 验证

- TypeScript、ESLint、生产构建和 ASAR 一致性检查通过。
- Vitest：247 个测试文件通过、2 个跳过；1780 项测试通过、2 个跳过。
- GitHub Actions 已生成 Developer ID 签名、公证的 macOS arm64/x64 包和 Windows x64 安装包。
- 三个平台均已完成真实 `0.3.5 -> 私有 0.4.1 候选` 的应用内下载、退出安装、自动重启和用户数据保留闭环。
- macOS arm64 签名候选已完成中文启动页、主界面、精选市场、详情抽屉、独立 Skill 页面和运行时连接验收。
- 更新清单请求能够通过唯一 `noCache` 参数和 `no-cache` 请求头绕过旧缓存，因此真实升级链路可用；服务器仍返回七天缓存响应头，基础设施缓存门禁尚未通过。

## 升级说明

- 正式发布获批后，已安装正式签名版本的用户可通过应用内更新升级；未签名或未公证构建仍需先手动安装正式签名版本。
- 第三方插件自动更新默认关闭；权限、许可证、脚本或网络域变化必须重新审查。
- 公共投稿市场不属于 0.4.1，后续单独立项。
