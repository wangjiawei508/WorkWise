## 目标

以“工程测量数据 → 可审查测绘成果”为 0.5.0 的唯一首发闭环，同时保留 WorkWise Electron + 现有 Runtime、Code/Write、Design、Flow、插件和既有 IM 能力。工程测量工作台使用现有线程、附件、TaskRun 和 Artifact 链，不建立第二 Runtime、第二队列或第二会话数据库。

候选成果基线（非正式交付）：

- 候选 DOCX 报告
- 候选 PDF 报告
- XLSX 数据与证据包
- `manifest.json` 成果依赖清单

上述内容不构成 F-OUT-11 所要求的开放格式、技术报告、归档/汇交或正式交付能力，也不代表过程检查、最终检查或合同验收已经完成。

PPTX 汇报、实时监测平台、跨项目仪表盘和外部 IM 触发器延期到 0.5.1，不阻塞 0.5.0。

工程测量数据源不能被简化为 CSV/XLSX。测量网络的 F-FMT-10 全链路（可视列映射、单位/角度确认、筛选和可保存复用的映射）尚未落地，因此测量网络 CSV/XLSX 当前一律 `archive-only`：不得作为未知厂商格式的回退解析，不得进入平差，也不得作为 P0 厂商格式已验收或候选验收的证据。仪器记录、GNSS 原始数据、行业交换格式、压缩封装和厂商私有二进制均须走各自的受理、预检和处置边界。

监测业务中的 CSV/XLSX 规范化、字段映射和质量分析是独立的数据处理链，不等同于测量网络导入；其可用性不解除上述测量网络 `archive-only` 门禁，也不能作为测量网络格式支持或 P0 验收的证据。

在 JSON 中，当前唯一可作为明确来源格式识别的是冻结的 `workwise-survey-network@1`。它只定义 WorkWise 的受控来源封装，仍必须经过来源完整性与预检门禁，且不能替代厂商 P0 格式的证据；其他通用、未声明或未冻结版本的 JSON 一律 `archive-only`。

## 专业测量源格式（M0 硬门禁，已按更新 PRD 收紧）

M0 仅以决策 D-03 的第一批 P0 格式为可验收目标：科傻 `.in1` / `.in2` / `.NET` / `.ou1` / `.ou2`、南方 DAT、Leica GSI8 / GSI16。每一种格式都必须具备真实脱敏样本、独立 golden/negative fixtures、显式单位/基准映射和候选包内验收记录，才可由目录显式提升为 `adjustment-ready`。南方 DAT 的列序仍为 Q-11 `n.a.`；在官方取证或用户签名确认映射前，必须保持 `archive-only`，不得默认或启发式猜测后放行。

第二、三批格式（包括 LandXML、RINEX、TDS/Carlson RAW/RW5、Sokkia SDR、DiNi/Zeiss M5、Trimble JobXML/JXL 与专有二进制）在本增量均不作为可平差支持承诺。可以按安全边界识别、保留原件并返回 `archive-only`、`converter-required` 或 `gnss-processing-required`，但识别、合成 fixture、扩展名、词法探测或未验收解析器都不能产生 `adjustment-ready`。

厂商私有二进制仍只能通过固定身份、版本、许可证、可执行文件哈希、参数、输入/输出哈希和无网络策略均已审计的本地转换器进入后续处理；没有转换器时必须保持 `converter-required` 或 `archive-only`。RINEX、RTCM、NMEA 及接收机原始文件可识别、检查和归档，但不是基线平差成果；只有固定基准、三维基线向量和完整协方差的处理结果才能进入 GNSS 平差内核。

格式注册表是版本化、可扩展的驱动边界，不把 P0 清单当作测绘行业格式全集。任何不在已验收目录中的格式必须安全识别或明确阻断，禁止回退成“未知文件按 CSV 读”，也不得将未来批次表述为本轮已支持。

每个导入源必须记录并展示：厂商、格式/版本、置信度、扩展名冲突、SHA-256、原文件保留状态、解析器/转换器、记录数、诊断、原始记录锚点和以下处置之一：

- `adjustment-ready`
- `gnss-processing-required`
- `converter-required`
- `archive-only`

当前实现状态：来源文件合约、原文件持久化、格式目录、安全的归档/阻断处置、冻结 `workwise-survey-network@1` 来源识别、GNSS 阻断、格式预检 UI、来源/就绪筛选和报告/XLSX/manifest 来源证据字段已经进入源码；原始文件哈希账本会在文件导入、校核和平差前重新验证。测量网络 CSV/XLSX 与通用 JSON 尚未取得可平差资格，必须保持 `archive-only`。已新增独立的派生观测值修正账本与只读回放：仅限来源字节和原始记录锚点均验证通过的单个 `observation.value`，保留前后值、理由、依据、操作者、时间与双链哈希，且永不回写原网络。它们只构成通用来源完整性机制的一部分，不等于 F-AUD-14 已完成，也不等于任何格式已获可平差资格。

本轮进一步将来源准入、平差证据、幂等重放、变形读取和候选交付串为同一条运行时校验链：每次新用途都会重新核对项目归属、来源准入、当前输入、持久化结果，以及 DOCX/PDF/XLSX/图表和 `manifest.json` 的公开字节。该“append-only + 哈希 + 重算”约束的是正常 Runtime/API 操作，不是对拥有 SQLite/schema/工作区直接写权限者的密码学防篡改保证；F-AUD 的正式可采信链路仍需外部签名/见证与跨实例事务性发布设计，不能以当前实现替代。

当前不提供浏览器侧“改数”写入，也不把派生视图自动注入平差；修正工序门禁、返工任务、签名、二级检查和正式交付仍是后续工作，不能因该基础能力而宣称规范合规或成果已批准。

除通过真实来源样本、独立金标、负向样本和打包应用验收的驱动外，所有厂商格式均保持 `archive-only`、`converter-required` 或 `gnss-processing-required`。不得将合成探测、文件扩展名、词法识别、转换器接口或目录条目表述为“已支持平差”；真实多厂商文件、许可核验、金标结果和打包应用验收仍未完成，因此候选构建继续后置。

## 数据与兼容性约束

- 不删除或改写旧线程、日志、插件、Skill、MCP、凭据引用、附件和数据库。
- 未知旧字段保持可读；缺失字段不强行迁移成工程线程。
- 原始数据不逐行发送给模型；数值、阈值、状态、引用、哈希由确定性 Runtime 生成。
- 所有变更接口继续使用 `expectedRevision` + `idempotencyKey`；重复提交复用原结果，过期修订稳定返回冲突。
- 第三方 Provider 配置、密钥、Base URL 和自动选模规则不修改。

## 最终判定

源码功能已覆盖计划的大部分业务面，但“计划内容全部完成”这一说法目前不成立：P0 真实格式证据、DAT 列序取证、打包依赖修复后的双架构候选、真实 P0 闭环、跨主题/窗口 UI、签名/公证、跨平台和专业人员验收仍未闭合。产品当前只能称为“源码候选”，不能发布 0.5.0，也不能用旧候选截图或旧测试数字替代验收。下一步必须从干净提交重建候选，完成 M0 门禁并由用户验收后，才可进入发布确认。
