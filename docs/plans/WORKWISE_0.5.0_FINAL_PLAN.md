## 当前判定：不可发布

0.5.0 目前仍是候选开发状态，不满足发布门禁。原因不是“还缺一张页面”，而是候选包和产品验收各有硬阻断：

- 旧候选包启动时缺少 `zod-to-json-schema`，已在 `d098554` 纳入正式依赖；必须用该修复后的新提交重新打包并启动验证。
- 候选尚未完成签名/公证、浅色/深色和窄窗口检查，也没有在打包应用内跑通真实 CSV/XLSX → 平差/分析 → DOCX/PDF/XLSX/manifest → 审查归档闭环。
- 视觉审查发现旧候选仍像“网页后台卡片堆叠”：AI 不是主工作面，测量页面缺少专业状态层级。当前源码已加入 Agent 状态带、工程上下文、网型/约束/观测权/可解性仪表带和点位成果复核摘要，但尚未在新候选包中验收。
- 本机完整测试受环境阻断：`better-sqlite3` 的 Node ABI（148/147）不一致以及 loopback 监听 `EPERM`；这不是通过编译就可以忽略的发布证据，需在匹配 Node/Electron 环境重新运行。

在上述证据全部通过并由用户确认安装后的 0.5.0 候选 UI 与功能前，不创建 Tag、不发布 Release、不提升 Stable。

## 目标

以“工程监测数据 → 可审查交付成果”为 0.5.0 的唯一首发闭环，同时保留 WorkWise Electron + 现有 Runtime、Code/Write、Design、Flow、插件和既有 IM 能力。工程工作台使用现有线程、附件、TaskRun 和 Artifact 链，不建立第二 Runtime、第二队列或第二会话数据库。

固定交付物：

- DOCX 正式报告
- PDF 正式报告
- XLSX 数据与证据包
- `manifest.json` 成果依赖清单

PPTX 汇报、实时监测平台、跨项目仪表盘和外部 IM 触发器延期到 0.5.1，不阻塞 0.5.0。

## 收口顺序

### A. 候选 GUI 验收（唯一当前代码阻塞）

3. 验证无项目、Runtime 离线、模型不可用、空/加载/部分/错误/过期状态均有可恢复动作。
4. 在浅色/深色和窄窗口分别检查三栏折叠、1px 分隔线、文字可读性和键盘焦点。
5. 用隔离真实 CSV/XLSX 完成导入、质量修正、趋势/异常/阈值分析、图表和四项成果校验；记录文件哈希、引用和 manifest。

## 数据与兼容性约束

- 不删除或改写旧线程、日志、插件、Skill、MCP、凭据引用、附件和数据库。
- 未知旧字段保持可读；缺失字段不强行迁移成工程线程。
- 原始数据不逐行发送给模型；数值、阈值、状态、引用、哈希由确定性 Runtime 生成。
- 所有变更接口继续使用 `expectedRevision` + `idempotencyKey`；重复提交复用原结果，过期修订稳定返回冲突。
- 第三方 Provider 配置、密钥、Base URL 和自动选模规则不修改。

## 最终判定

源码功能已覆盖计划的大部分业务面，但“计划内容全部完成”这一说法目前不成立：打包依赖修复后的候选、真实闭环、跨主题/窗口 UI、签名/公证和匹配环境的完整测试仍未闭合。产品当前只能称为“源码候选”，不能发布 0.5.0，也不能用旧候选截图或旧测试数字替代验收。下一步必须从 `d098554` 之后的干净提交重建候选，完成 A/B/C 三组门禁并由用户验收后，才可进入发布确认。
