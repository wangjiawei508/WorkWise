日期：2026-07-25（上海时间）

## 范围

本轮验收覆盖：

- 用户提供的 Tender Master 招投标 Skill 与 Agent。

### 专项回归

- 内置 Skill 安装、修复、来源 metadata 和用户同名非托管包保护。
- Tender Agent 不可修改、最高权限为 `workspace-write`，不允许 Shell 与 MCP。
- 活动会话 Agent 选择、保存中禁用发送、一次精确 revision 冲突重放。
- Tender 货物、软件/服务、工程监测三类确定性测试夹具的要求提取、评分排除、证据和终稿阻断。
- Tender 报价脚本不使用隐式示例数字，不接受负数、无穷值或缺少配置。
- DOCX 只在生成真实 OOXML 时成功，依赖缺失或格式不安全时明确失败。
- Document Illustrator 不包含旧版凭据脚本，不读取第三方 `.env` 或旧 Agent 路径。
- 图片工具把真实 PNG/JPEG/WebP 写到工作区相对路径，并拒绝越界、符号链接和 junction 引用。
- 非视觉模型只能报告文件/格式/尺寸检查，不能声称已经检查图片像素。
- 三个受限来源没有进入 `src/asset/skills`，递归文本扫描也没有发现其固定提交或源码地址。
- 中文和英文市场文案完整；受限项目显示外部链接按钮，不显示误导性的安装按钮。

## 尚未冒充通过的项目

- 当前 `~/.workwise/runtime/config.json` 的 `imageGeneration` 配置为空，不能进行
  真实第三方图片服务的端到端调用。已用确定性测试提供商验证真实图片文件、
  扩展名规范化、工作区插入路径和失败关闭行为；未配置提供商时必须明确失败，
  本记录不声称已经生成真实业务图片。
- Computer Use 超时的根因已定位为候选包和 `/Applications/WorkWise.app` 同时启动，
  且按应用名称查询会再次拉起已安装版本。关闭冲突实例并按候选应用绝对路径控制后，
  已在 `candidate-installers-0.3.2-51` 的 Apple Silicon 客户端中再次真实确认：
  - 聊天输入区可以选择“招投标编制专家”，选择后显示值正确；
  - Skill 市场可见 `Tender Master`、`Bidding Knowledge` 与
    `Document Illustrator`，均显示已添加；
  - Social Card、Material Illustration、Logo Generator 只显示来源/授权提示，
    没有安装动作。
- 前一候选包的实际货物采购短场景暴露出事实边界缺陷：在用户只明确提供 IP67、
  72 小时和三年质保时，Agent 擅自把制造商唯一授权、ISO 体系证书、近三年业绩等
  行业惯例升级为本项目硬性条件。`ee03408815701045c3b503667e71ecb08bb563ac`
  已修复该事实边界。
- `candidate-installers-0.3.2-51` 的同场景复测确认：三项硬性要求只来自用户输入，
  制造商授权、业绩、MTBF 等均被隔离为“未确认是否为本项目要求”的建议，没有再
  冒充资格条件或阻断项；但 Agent 仍主动追加四项建议、结论和下一步，显著超过
  “不超过 500 字、只输出表格”的明确响应合同，因此该场景仍判定为失败。
- 前一候选包的未配置图片提供商场景最终正确报告“未生成”，但仍先读取参考资料、
  创建目录和配图计划，耗时约 1 分钟并使用约 19.7 万 Token，失败关闭过晚。
- 上述事实边界与图片能力门禁缺陷已在提交
  `ee03408815701045c3b503667e71ecb08bb563ac` 修复：
  - Tender Agent/Skill 只允许把明确来源条款列为硬性要求，行业惯例必须隔离为
    “建议核实”，并禁止猜测未读取文件内容；
  - Document Illustrator 在读取文档、建目录或写计划前执行图片能力门禁。
- 对最新实测发现的篇幅/格式遵从缺陷，已在后续工作树中进一步收紧响应合同：
  字数、固定字段、固定行数和“只输出某种结构”优先于默认模板，未明确要求时不得
  追加建议、结论、下一步或解释；该修复需重新构建候选并复测。
- 三类招投标短场景只有在新候选中均不新增未提供条件并遵守格式后才可通过；
  配置图片提供商后的真实业务图片生成仍需要用户提供有效服务配置，本记录不会以
  测试桩代替。

## 候选结论

三平台构建、稳定性、包结构、版本、校验和、来源和许可证边界已经通过；但是，
实际安装界面中的 Skill/Agent 可见性已通过，但实际场景发现的问题刚完成修复，
新候选复测和已配置图片提供商的真实文档配图仍未通过。
所以当前结论是：

- 包结构候选：通过。
- 专项真实效果候选：未通过，暂未达到公开发布条件。

恢复 Computer Use 或取得人工实际界面证据，并配置图片提供商完成真实 E2E 后，
才能勾选 OpenSpec 2.5、3.4 和 5.6。若要把三个受限项目改为内置，还必须先完成
书面授权任务 4.3。不得依据本记录创建版本标签或公开 Release。
