# Static linear observation append — full trial workspace integration

The `static-incremental` trial uses the frozen `declared-static-linear-append-1` pure kernel. It is the sixth advanced-trial kind. Existing generalized-W, VCE, Huber, statistical-family and reference-datum records and resource limits remain compatible.

The authenticated Runtime HTTP/IPC path requires the complete original declaration, model basis, explicit trial acknowledgment, project revision and idempotency key. Raw UTF-8 request/declaration bytes and model basis are preserved separately from schema-normalized values. SQLite is append-only with update/delete/replace triggers. Restore, history, reverify and export verify binding, environment, hashes and a fresh calculation; stale, corrupted and incompatible records remain unavailable. This stores independent trial records; it does not alter a formal survey network or make the kernel's supplied base a verified prior Runtime state.

Static summaries explicitly expose `baseObservationCount`, `appendedObservationCount` and total `observationCount`. Only this kind admits up to 256 total observations, 128 added observations and 16 parameters; the previous kinds retain their 128-observation summary maximum and forbid the new counters. A static model costs `ceil((n*p^2 + appended*p^3)/36864)` with minimum 1 and maximum 16 work units. A ten-record maximum-model page costs `1 + 10*(3+16) = 191`, below the existing 240-unit/minute budget. Maximum-size long-Chinese-ID input and exported record measurements are in `capacity-result.json`; `capacity-replay.mjs` reproduces them on compiled Node ESM. Timing is one local observation, not an SLA.

Renderer checks the raw declaration binding, returned request hash, computed base/final fingerprints and complete base/updated QR state hashes using Web Crypto; no numerical Node implementation enters the renderer. Bilingual UI shows parameter estimates, both full prior covariance matrices, posterior diagnostic-only meaning, every appended observation's rotation/residual/state, batch comparison and source/model uncertainty. The existing native Save As export replays the server record and preserves the raw declaration; cancellation remains cancellation. The synthetic example is data-only and has a precomputed valid semantic fingerprint.

Validation: 74 Runtime/HTTP/wiring tests, 42 desktop IPC/DOM tests, full root and kun TypeScript checks, targeted ESLint and full `npm run build` passed. Existing happy-dom asynchronous React act warnings appear in the test log; all assertions pass. These are automated functional checks, not packaged visual acceptance. Parent integration owns the packaged app, supported themes/window-size screenshots and user UI acceptance. No release, public version, tag, feed, official site or quality-scoring workspace change is included.
